# Architecture — v0.3

## Components

### Google Sheet

`All Items` remains the recipe-requirement source. Control tabs hold deterministic rules and approved catalog data. Output tabs are regenerated by Apps Script. `Daylight Matches` is a staging table for public-catalog candidates.

### Google Apps Script

Apps Script:

- reads workbook tabs and the linked spice inventory;
- sends normalized inputs to the backend;
- writes weekly order, exclusion, review, and Daylight-match outputs;
- lets the user approve a selected Daylight candidate into `Product Catalog`;
- preserves checklist state by stable ID; and
- records shopper/checkoff information.

### FastAPI backend

The backend:

- canonicalizes ingredients and selects the requested week;
- applies exclusions and overrides;
- aggregates compatible quantities;
- selects approved catalog products and calculates integer package counts;
- crawls and caches Daylight's public catalog;
- parses Daylight package/UOM patterns and ranks candidates; and
- keeps Instacart credentials server-side.

## Source row lifecycle

```text
All Items row
  → week selection
  → canonical ingredient
  → weekly override
  → fulfilled/stocked/spice/bulk-meat rules
  → quantity validation
  → weekly aggregation
  → approved Product Catalog match?
      yes → package optimization → Weekly Order
      no  → Needs Review → Daylight public search → Daylight Matches
              → human approval → Product Catalog → regenerate
```

## Daylight adapter

The adapter reads the public paginated catalog, checks `robots.txt`, uses a descriptive user agent, limits concurrency, and caches a normalized snapshot. Search does not call the website once per ingredient; one snapshot is reused for batch matching.

Normalized product metadata:

```json
{
  "product_name": "APPLE, FUJI 5-LB",
  "product_url": "https://daylightfoods.com/product/apple-fuji-5-lb/",
  "uom": "EACH",
  "product_id": "apple-fuji-5-lb"
}
```

The package parser produces:

```json
{
  "amount_per_package": 5,
  "package_unit": "lb",
  "pack_count": 1,
  "purchase_unit": "each",
  "exact": true
}
```

Public-catalog approval creates an active Product Catalog row but adds a marker indicating that account price and live availability were not confirmed. The recommender lowers these rows to medium confidence.

## Stable identifiers

Recommendations receive a deterministic stable ID from the week, canonical ingredient, retailer, and product identity. Apps Script uses it to retain Bought, Shopper, Checked By, Checked At, and Notes.

## Extension points

1. Import a Daylight account order guide or official API feed for account prices and availability.
2. Refresh approved Weee product links through an authorized interface.
3. Add Costco Same-Day product identifiers through Instacart access.
4. Add pantry carry-forward inventory and reorder thresholds.
